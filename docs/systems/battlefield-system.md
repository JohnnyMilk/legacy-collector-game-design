# 戰場系統（Battlefield System）

## 系統定位

《LEGACY COLLECTOR》採用固定方格戰場。Combat Demo v0.1 以簡單、可預測、可直接計算為原則，優先驗證移動、站位、射程、阻擋與技能互動，不在首版加入高低差、面向或複雜地形成本。

## 地圖規則

- 戰場為 **8×8 正方形 Grid**。
- 俯視角。
- 無高度差。
- 無角色面向。
- 一格最多存在一個正式戰鬥單位。
- 一般移動只使用上、下、左、右四方向。
- 不存在通用背擊、側擊或面向傷害加成；站位優勢主要透過包圍暴擊與技能範圍表現。

## 距離

一般距離使用 **Manhattan Distance**：

`Distance = |x1 - x2| + |y1 - y2|`

因此斜對角相鄰格的 Manhattan Distance 為 2，而不是 1。

8×8 棋盤在單一直線方向上的最遠有效延伸為 **7 格**。因此舊 9×9 規格中若技能明確寫成「最遠 8 格」的直線射程，現行規則應調整為「最遠 7 格」。

但「周圍 8 格」不是射程 8，而是指角色周圍八個相鄰格；此幾何定義不因棋盤由 9×9 改為 8×8 而變更。若技能明確使用「周圍 8 格」「斜向」「8 方向」或其他特殊幾何範圍，則依技能文字處理，不強制套用 Manhattan Distance。

## 一般移動

角色一般移動距離由職業 MOVE 決定。

Combat Demo v0.1 的普通可行走地面：

- **Floor**：移動成本 1。
- **Wall**：不可進入、不可穿越。

角色只能移動到存在合法路徑且總移動成本不超過 MOVE 的格子。

例如 MOVE 3 代表最多消耗 3 點移動成本，不代表可跨過牆體直接抵達直線距離 3 的位置。

Demo v0.1 的普通移動尋路可使用等成本 BFS；未來若加入不同地形移動成本，再改用適合加權路徑的演算法。

## 單位穿越與佔格

### 友軍

- 可穿越。
- 穿越友軍所在格仍以正常地面成本計算。
- 不可停留在友軍已佔據的格子。

### 敵軍

- 不可穿越。
- 不可停留在敵軍已佔據的格子。

### 其他

- 一格最多一個正式戰鬥單位。
- 牆體與其他明確不可通行物件不可被單位佔據。
- 分身與召喚物若具有正式戰鬥單位身分，使用相同佔格規則，除非技能另有明確例外。

## 一般移動與行動順序

一般行動可依 Action System 使用：

- 移動 → 行動
- 行動 → 移動
- 僅移動
- 僅行動
- Wait

一般移動每次自身行動最多使用一次，不能拆成「先走一部分 → 行動 → 再走剩餘一般移動」。

技能明確提供的額外位移、瞬移、交換位置或技能內建移動不受此限制，依技能文字處理。

## 技能瞄準方向

移動規則與技能瞄準規則分開處理。

- 基礎移動固定使用上、下、左、右四方向。
- 技能是否可使用斜向格，由個別技能自行定義。
- 若技能標示支援 8 方向，則可使用上、下、左、右、左上、右上、左下、右下進行直線瞄準或延伸。
- Tier 2「鍊金術師」的「藥劑投擲」明確支援 8 方向：命中起始格後沿同一方向繼續向前延伸 2 格，因此斜向投擲時也形成連續 3 個斜向有效格。

## 遠程攻擊與 Line of Sight

一般遠程攻擊與一般遠程技能的預設 Line of Sight 規則：

- **中間的戰鬥單位不阻擋射線。**
- **牆體阻擋射線。**
- 其他物件是否阻擋，由物件或技能規則明確定義。

因此友軍或敵軍站在攻擊者與目標之間，預設不會使一般遠程攻擊失效；牆體則會阻擋。

個別技能可以覆蓋此規則。例如：

- 軍團守衛「戰槍」的後方格會受到地形阻擋。
- 空間魔導士「魔導劍」明確不被中間阻擋。

技能文字永遠優先於一般 Line of Sight 規則。

## 死亡與格子釋放

單位 HP 歸零後，先依死亡系統結算立即死亡觸發與復活效果。

若最後確認為**正式死亡**：

- 單位立即從戰場移除。
- 原本佔據的格子立即釋放。
- 該格重新依原本地形規則決定是否可通行／可停留。

目前不建立通用屍體阻擋系統。若未來技能需要「屍體」作為對象，應由該系統另外建立 Corpse Object，而不是讓所有死亡單位預設留下阻擋物。

## Combat Demo v0.1 地形範圍

首版只需要：

| 地形 | 可通行 | 移動成本 | 阻擋 Line of Sight |
|---|---|---:|---|
| Floor | 是 | 1 | 否 |
| Wall | 否 | — | 是 |

暫不加入：

- 森林移動成本。
- 沼澤。
- 山地。
- 高低差。
- 地形命中／閃避／攻防補正。

這些可以在 Combat Core 穩定後再逐步加入，不阻塞首個 Vertical Slice。

## Demo Runtime 原則

Combat Demo 應從正式 Battlefield runtime data 讀取：

- Grid 尺寸。
- 距離規則。
- 基礎地形。
- 移動成本。
- 單位穿越／佔格規則。
- Line of Sight 規則。
- 死亡格釋放規則。

不要在 Demo JavaScript 中另建一套不同的戰場常數。

## 平衡狀態

以上為 **Combat Demo v0.1 正式基準規則**。目前棋盤固定為 8×8；未來若實測顯示 MOVE 2～4 的實際節奏或 Line of Sight 過於寬鬆／嚴格，可以再依實測調整，但任何修改都必須同步 Markdown 與 runtime data。

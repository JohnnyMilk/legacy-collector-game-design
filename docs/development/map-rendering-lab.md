# 地圖渲染研究專區

> 狀態：🔴 進行中 / 尚未定案

這個頁面專門用來研究《遺產收集者》的**戰場地圖視覺渲染**。目前 Combat Demo 的地圖優先驗證戰鬥規則與操作，因此視覺仍偏功能性；後續會在不破壞戰棋資訊可讀性的前提下，逐步建立正式地圖表現。

## 目前基準

- 戰場尺寸：8 × 8。
- 方格仍是戰鬥判定的基本單位。
- 地圖必須支援手機、iPad 與桌面瀏覽器。
- 單位、血條、行動提示、移動範圍、攻擊範圍與障礙物必須保持清楚可讀。
- Combat Demo 0 / Demo 1 目前以簡單色塊與格線作為功能性基準。

## 研究目標

### 1. 地表渲染

研究如何讓同一種地形不再像完全相同的 64 個方格，例如：

- 基礎地表色差與紋理變化
- 相鄰格視覺連續性
- 地表邊緣與區域過渡
- 非規則的小型裝飾細節
- 保留格線判讀但降低「試算表」感

### 2. 障礙物與場景物件

目前障礙物主要是戰鬥功能標記。後續研究：

- 牆、岩石、樹木、廢墟、箱體等視覺類型
- 可通行／不可通行的視覺語言
- 是否允許物件超出單格視覺邊界
- 物件遮擋單位時的處理方式

### 3. 戰術提示層

地圖美術不能降低操作辨識度。需獨立研究：

- 目前行動角色提示
- 可移動格
- 攻擊／技能合法目標
- 技能預覽範圍
- 選取格
- 危險區域

這些提示應視為獨立的 **Combat Overlay Layer**，而不是直接寫死在地表美術中。

### 4. 地圖主題與 Region 差異

未來不同 Region 可以共享戰鬥規則，但使用不同的視覺資產與渲染參數。主題內容目前 TBD，不在本頁提前定案。

### 5. 效能與資產策略

Browser-first 是正式限制，因此需要比較：

- CSS procedural / pattern
- 單格 Tile 圖片
- Tile atlas / sprite sheet
- 多層 PNG / WebP
- SVG
- Canvas 2D
- DOM + CSS 與 Canvas 混合方案

評估項目至少包含：手機效能、載入量、縮放品質、透明度、維護成本、地圖主題擴充成本。

## 重構原則

地圖視覺研究**不得把 Demo 專用寫法繼續堆進共用 Combat UI**。正式實作前仍需重構。

預定架構方向：

```text
Combat Rules / Model
        ↓
Battlefield State
        ↓
Map Renderer
 ├─ Ground Layer
 ├─ Object Layer
 ├─ Unit Layer
 └─ Combat Overlay Layer
```

原則：

1. `combat-model.js` 保持戰鬥規則與狀態，不承擔地圖美術。
2. 地圖資料描述「是什麼」，Renderer 決定「怎麼畫」。
3. Demo 0、Demo 1 與未來 Demo 共用同一套 Map Renderer，不複製渲染邏輯。
4. Region / Map Theme 應以資料或資產設定切換，不建立一套新的 Combat App。
5. 視覺提示層與地表層分離，避免未來換地圖美術時破壞戰鬥操作。
6. 在正式增加地圖渲染功能前，先檢查並拆分目前 `combat-app.js` / Combat UI 中過度集中的責任。

## 第一階段研究順序

1. **盤點現有 Battlefield DOM / CSS 結構**。
2. **重構 Map Renderer 邊界**，先保持目前畫面完全不變。
3. 建立一個不影響正式 Demo 規則的地圖視覺實驗區。
4. 比較 2–3 種低成本地表渲染方案。
5. 確認手機與 iPad 的可讀性與效能。
6. 再決定正式地圖資產規格與 Region Theme 格式。

## 暫不定案

以下項目目前只列為研究題目，不視為正式規格：

- 是否使用手繪 Tile
- 是否使用程序式地圖紋理
- 是否改用 Canvas
- 地圖是否採斜視角／等角視角
- 地形高度差
- 動態光影、天候、粒子
- Region 的正式美術風格

在 Combat Demo 1 測試期間，本頁只作為研究與重構工作的專區，不改動已確認的戰鬥規則。

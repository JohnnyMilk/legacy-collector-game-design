# 職業綁定型戰術 RPG｜戰鬥屬性架構提案

> **文件狀態：獨立架構提案（PROPOSAL / NOT ADOPTED）**
>
> 本文件保存可供未來遊戲使用的戰鬥屬性架構，不代表《LEGACY COLLECTOR》已確認採用，也不得覆蓋現行 Combat Rule、既有職業數值或已完成的 Combat Test 結論。

## 1. 設計前提

本提案適用於以下類型的戰術 RPG／SLG：

- 角色以「職業」為主要身分。
- 武器與職業綁定，玩家不能自由更換武器。
- 角色本體具有獨立能力值。
- 普通攻擊、主動技能、被動技能、Mastery 與特殊狀態可以修改單次行為。
- 不同職業互相博弈時可以形成優勢與劣勢，但不能因屬性差距而永久無法命中、無法迴避或無法造成傷害。
- 戰鬥需要保留有限的機率性，同時讓玩家可以理解與預測結果。
- 系統必須適合資料驅動實作，避免每個技能各自建立一套例外程式。

## 2. 核心方向

本提案採用三層結構：

1. **角色／職業 Profile**：描述角色本體的生命、攻防、速度、命中專長與迴避能力。
2. **技能 Attack Profile**：每個技能自行描述射程、命中修正、攻擊倍率、段數、穿透與特殊標籤。
3. **Modifier Pipeline**：Mastery、Buff、Debuff、被動、地形與特殊規則，以統一格式修改本次行為。

設計精神可概括為：

> **TOW 式角色差異 × AoS 式技能 Profile × 資料驅動 Modifier Pipeline**

這是設計概念的融合，不是複製任何一套桌上遊戲的完整擲骰流程。

## 3. 武器與職業的關係

本提案不設計自由武器更換。

- 武器是職業設計的一部分。
- 職業決定角色可以使用哪些普通攻擊與技能。
- 所謂「武器 Profile」，在程式與企劃資料中實際上等同於「Attack Profile」或「Skill Profile」。
- 同一職業仍可擁有多種不同攻擊行為，例如普通斬擊、重擊、突進、投擲、副手攻擊或覺醒技能。
- Profile 的目的不是建立裝備系統，而是讓每個技能可以擁有不同戰鬥參數。

因此，即使角色不能換武器，AoS 式的攻擊 Profile 仍然有價值。

## 4. 角色／職業 Profile

建議的核心屬性如下。實際命名可以依遊戲世界觀調整。

| 屬性 | 用途 |
|---|---|
| HP | 可承受的總傷害 |
| ATK | 物理攻擊強度 |
| MATK | 魔法攻擊強度 |
| DEF | 物理防禦 |
| MDEF | 魔法防禦 |
| AGI | 行動順序、速度型效果 |
| MOVE | 地圖移動距離 |
| WS | 近戰攻擊的基礎命中能力 |
| BS | 遠程攻擊與需要瞄準之投射技能的基礎命中能力 |
| EVA | 對所有可迴避攻擊的防禦性命中修正 |

### 屬性設計原則

- 高 ATK 不代表高命中；力量與技巧可以分開。
- 高 AGI 不必然等於高 EVA；先行動與難以命中可以分開平衡。
- MATK 與 MDEF 保留魔法職業的獨立設計空間。
- HIT 若要拆分為 WS／BS，應以「取代 HIT」的方式處理，避免堆疊成三套命中屬性。
- 若遊戲不需要區分近戰與遠程準確度，可以保留單一 ACC；WS／BS 並非必要欄位。

## 5. 技能 Attack Profile

每個普通攻擊與主動技能擁有自己的攻擊資料。

```js
{
  id: "weakness-break",
  name: "弱點破壞",
  style: "melee",
  damageType: "physical",
  range: 1,
  accuracyStat: "WS",
  accuracyModifier: 10,
  powerMultiplier: 1.6,
  hits: 1,
  penetrationPct: 20,
  canCrit: true,
  canEvade: true,
  traits: ["melee", "armor-breaker"]
}
```

### 主要欄位

| 欄位 | 說明 |
|---|---|
| style | melee、ranged、magic 等行為分類 |
| damageType | physical、magic、true 等傷害類型 |
| range | 射程或作用距離 |
| accuracyStat | 使用 WS、BS、固定命中或其他命中來源 |
| accuracyModifier | 此技能比角色基礎命中更準或更不準 |
| powerMultiplier | 技能傷害倍率 |
| hits | 單次技能包含的攻擊段數，不代表額外完整回合 |
| penetrationPct | 命中後忽略多少 DEF／MDEF |
| canCrit | 是否能暴擊 |
| canEvade | 是否允許目標迴避 |
| traits | 供被動、AI、UI、Log 與特效辨識的共用標籤 |

角色提供「使用者的能力」，技能提供「這個行為的特性」。同一角色施放不同技能時，最終命中、倍率、穿透及段數可以不同。

## 6. 命中、迴避與穿透必須分開

這三個概念不能混為同一項判定。

### 命中與迴避

命中／迴避發生在攻擊接觸目標以前，用來回答：

> 這次攻擊是否成功碰到目標？

建議概念公式：

```text
最終命中率 =
clamp(
  最低命中率,
  最高命中率,
  攻擊者命中屬性
  + 技能命中修正
  + Buff / Debuff / 地形修正
  - 目標 EVA
)
```

其中：

- 近戰技能通常讀取 WS。
- 遠程技能通常讀取 BS。
- 不需要瞄準的地面範圍技能可以設定為固定命中或不可迴避。
- `clamp` 保證最終結果不會低於最低命中率，也不會高於最高命中率。

### 穿透

穿透發生在攻擊已經命中之後，用來回答：

> 目標的防禦有多少能夠抵消本次傷害？

建議概念公式：

```text
有效防禦 = 對應 DEF 或 MDEF × (1 - 穿透率)
傷害 = 攻擊強度 × 技能倍率 - 有效防禦
```

因此：

- **命中率低**：容易 MISS。
- **EVA 高**：降低對方命中率。
- **穿透高**：命中後比較能突破防禦。
- **DEF／MDEF 高**：被命中後減少傷害。

穿透不等於命中，也不等於迴避。

## 7. 避免極端硬封鎖

職業克制應形成「優勢」，而不是「完全禁止互動」。

### 最低與最高命中率

系統應具有全域命中率上下限：

```js
const MIN_HIT_CHANCE = tuning.minHitChance;
const MAX_HIT_CHANCE = tuning.maxHitChance;
```

候選調校方向：

| 戰鬥風格 | 最低命中率候選 | 最高命中率候選 | 特性 |
|---|---:|---:|---|
| 高波動戰術型 | 15%～25% | 95% | 屬性差異明顯，逆轉機率低但存在 |
| 中度穩定型 | 30%～40% | 95% | 克制清楚，但較少完全浪費回合 |
| 高穩定型 | 60%～80% | 95%～100% | 更接近確定性戰鬥，MISS 只作為小幅變化 |

以上數值只是候選區間，尚未確認。應由實際回合長度、技能成本、單位數量與失誤懲罰共同決定。

### 傷害下限

若遊戲不希望高防禦職業完全封鎖低攻擊職業，可再加入最低傷害規則：

```text
最終傷害 = max(最低傷害, 計算後傷害)
```

但最低傷害不宜過高，否則 DEF／MDEF 將失去價值。

### 必中與不可迴避

必中技能可以存在，但必須是技能特性或資源交換，而不是常態：

- 傷害倍率較低。
- 冷卻較長。
- 需要蓄力或特殊條件。
- 只能針對特定距離或狀態。
- 不代表同時無視 DEF／MDEF。

同理，高 EVA 角色可以非常難命中，但仍受到最低命中率保護。

## 8. Modifier Pipeline

Mastery、被動與狀態不直接改寫技能程式，而是以資料描述條件與效果。

```js
{
  source: "memory-awakening-weakness-break",
  timing: "beforeDefense",
  conditions: [
    {
      left: "target.DEF",
      operator: ">=",
      right: 40
    }
  ],
  effects: [
    {
      type: "addPenetrationPct",
      value: 30
    }
  ]
}
```

「弱點破壞」可以被解讀為：

> 對高 DEF 目標攻擊時，本次攻擊額外獲得 30% 物理穿透。

這比「高 Toughness 時強制改成 4+ 傷害判定」更適合電玩式 SLG，因為：

- 不增加第二次命中／受傷擲骰。
- 玩家較容易預估結果。
- Combat Log 可以清楚說明觸發原因。
- AI 能讀取條件與收益。
- 相同效果可以被其他技能重複使用。
- 不需要在每個技能中加入客製化巢狀 `if`。

## 9. 建議的統一處理順序

```text
讀取角色／職業基礎值
→ 套用長時間 Buff／Debuff
→ 建立本次 Attack Profile
→ 套用技能、Mastery、被動與地形 Modifier
→ 計算並限制最終命中率
→ 進行一次命中判定
→ 命中後計算穿透與有效防禦
→ 計算傷害、暴擊與最低傷害
→ 套用命中後狀態
→ 輸出 Combat Log 與 Floating Combat Text
```

所有職業與技能都走同一條處理流程；差異來自資料，不來自散落在各技能中的例外程式。

## 10. 職業博弈範例

| 對戰情境 | 預期結果 |
|---|---|
| 高 WS 戰士攻擊高 EVA 刺客 | 命中率下降，但不會降至 0% |
| 低 WS 重裝騎士攻擊刺客 | MISS 較多；一旦命中仍可造成高傷害 |
| 刺客攻擊高 DEF 騎士 | 普通攻擊受防禦壓制；弱點／穿透技能可改善 |
| 法師攻擊高 MDEF 支援職業 | 魔法傷害降低，但不影響法術是否命中 |
| 弓手攻擊低 EVA 法師 | BS 優勢提高命中穩定度，但仍受最高命中率限制 |
| 必中法術攻擊高 EVA 目標 | 跳過 EVA 判定，但仍須處理 MDEF |

這能形成軟性克制：

- 克制方有明顯優勢。
- 被克制方仍能行動與造成結果。
- 技能選擇可以部分反轉職業劣勢。
- 不會因單一屬性差距直接決定勝負。

## 11. 程式實現原則

### 應採用

- 角色、職業、技能與 Modifier 使用 JSON 或純資料物件。
- 公式集中在 Combat Resolver。
- 狀態使用統一的 timing 與 effect type。
- 命中率上下限由全域 tuning 設定。
- 所有隨機結果可注入亂數種子，以便測試重現。
- Combat Log 保存原始值、修正值與最後結果。
- 對 Profile 與 Modifier 建立 schema validation。
- 對每個運算階段建立單元測試。

### 應避免

- 每個技能直接操作角色最終數值。
- 在技能內大量建立客製化 `if / else`。
- 同一個效果使用多種不同欄位名稱。
- 把命中、迴避、穿透與暴擊混在單一公式。
- 讓多段攻擊等同多個完整行動。
- 讓任何一般職業組合出現永久 0% 命中率。
- 為了模仿桌遊而增加不必要的多層擲骰。

## 12. 實作成本評估

| 項目 | 成本 | 說明 |
|---|---:|---|
| Attack Profile 資料格式 | 低～中 | 主要是統一現有攻擊欄位 |
| 命中率上下限 | 低 | 集中在命中 Resolver 即可 |
| 穿透 | 低～中 | 在有效防禦階段增加計算 |
| WS／BS 分流 | 中 | 需要角色資料、UI、敵人與技能遷移 |
| hits 多段攻擊 | 中 | 需要處理逐段 Log、暴擊與觸發次數 |
| Modifier Pipeline | 中～高 | 初期架構成本較高，長期可減少技能特例 |
| 完整 S/T 傷害表 | 高 | 增加資料轉換、擲骰層級與平衡負擔，不建議 |
| 士氣、面向與隊形 | 高 | 牽涉 AI、路徑、地圖與 UI，本提案不包含 |

## 13. 與《LEGACY COLLECTOR》的關係

目前只保存為未來設計參考。

- 不修改《LEGACY COLLECTOR》現行角色能力值。
- 不修改已確認傷害公式。
- 不修改現有 HIT／EVA 規則。
- 不修改普通攻擊與技能倍率。
- 不影響 Region 0～2、Boss 2A、Boss 2B 的既有測試結果。
- 若未來考慮導入，必須先建立隔離 Prototype，再做回歸測試。
- 未經正式確認，不得將本提案內容寫入現行 Combat Rule。

## 14. 決策摘要

本提案的推薦版本是：

> 角色以職業為核心且不能更換武器；角色本體提供基礎能力值，每個技能具有獨立 Attack Profile，Mastery 與狀態透過統一 Modifier Pipeline 修改本次行為。命中／迴避採用具有上下限的機率公式，確保職業差距形成軟性克制而非完全封鎖；穿透只在命中後處理 DEF／MDEF，不與命中判定混用。

## 15. 待決策項目

未來若要把此架構用於新遊戲，仍需逐項確認：

- 是否使用 WS／BS，或只使用單一 ACC。
- 最低與最高命中率。
- 是否設定最低傷害。
- 暴擊是否獨立擲骰。
- 多段攻擊每段是否獨立命中。
- 穿透採百分比、固定值或兩者並存。
- 魔法投射技能使用 BS、專屬施法命中，或固定命中。
- 哪些 AoE 技能可以被 EVA 迴避。
- Modifier 的疊加順序與上限。
- 是否將此提案導入《LEGACY COLLECTOR》，或只用於其他未來作品。

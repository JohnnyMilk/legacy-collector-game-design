# LEGACY COLLECTOR｜開發與呈現原則

## 頁面用途

本頁記錄《LEGACY COLLECTOR》的長期開發理念、技術選擇與視覺呈現原則。未來在設計戰場、事件、角色對話、敵人、Boss、手機介面與 Prototype 時，都應優先回到本頁確認是否仍符合「低資產、Browser-first、保留玩家想像空間」的方向。

## 核心開發理念

《LEGACY COLLECTOR》不以大量美術資產、動畫、3D 場景或傳統大型遊戲引擎為前提。

目標是使用最簡單、最可維護、最容易跨平台執行的 Web 技術，讓遊戲能直接在瀏覽器中運行，並自然支援桌機、平板與手機。

核心原則：

- **Browser-first**：優先以瀏覽器為主要執行環境。
- **HTML + CSS + JavaScript**：作為主要技術棧。
- **低美術資產依賴**：不把大量角色動畫、場景 CG、3D 模型或高成本特效列為必要條件。
- **資料驅動**：職業、敵人、事件、Region、對話等盡量以 JSON 資料描述。
- **MVP-first**：先完成最小可玩的完整循環，再逐步增加事件、職業、Boss、敘事與特殊表現。
- **跨裝置**：同一套程式碼優先支援桌面瀏覽器、iPad 與手機。

## 技術方向

### 主要技術

優先使用：

- HTML
- CSS
- Vanilla JavaScript
- JSON

MVP 階段不強制使用 React、Vue、Phaser 或其他大型框架／遊戲引擎。

若未來確實出現原生 DOM 難以維護的規模，再重新評估是否導入額外框架；但框架不是目前的前提。

### 建議資料分層

遊戲規則與內容應盡量分開：

```text
/index.html
/css/
  game.css
/js/
  game.js
  battle.js
  map.js
  event.js
  character.js
/data/
  classes.json
  enemies.json
  events.json
  regions.json
  dialogue.json
```

實際檔案可以隨開發調整，但原則是：

- HTML 負責畫面結構。
- CSS 負責視覺呈現與 Responsive Layout。
- JavaScript 負責遊戲規則與互動。
- JSON 負責可編輯的遊戲資料。

目前 GDD 中已經存在的結構化資料，應盡可能往未來可直接被遊戲讀取的方向維護，避免企劃資料與正式遊戲資料完全分離。

## 視覺方向：Symbolic Tactical Roguelike

《LEGACY COLLECTOR》的視覺精神可參考 NetHack 類型遊戲的「符號化、資訊化、留白」，但不需要複製傳統純 ASCII 的簡陋程度。

正式方向可理解為：

**NetHack 式符號化資訊呈現 × 現代 CSS UI × 戰術格子戰鬥 × 文字敘事 × 少量視覺效果。**

可以使用：

- 中文字元、英文字母、符號、簡單 Icon 作為角色與敵人的主要識別。
- CSS 邊框、背景、陰影、透明度、字體層級與狀態色增加辨識度。
- CSS transition / animation 做必要的命中、受傷、選取、Charge、移動與狀態提示。
- 少量靜態背景圖或裝飾素材，但不把它們設計成遊戲運作的必要條件。

### 保留想像空間

遊戲不需要把角色、敵人、世界與每一個動作全部具象化。

玩家可以逐漸對符號產生角色認知，例如戰場中的「玄」「幻」「星」「聖」或其他固定標誌。

本作希望提供世界的輪廓，而不是替玩家填滿所有畫面。

**我們提供世界的輪廓，玩家用自己的經歷完成它。**

這與《LEGACY COLLECTOR》的核心命題一致：真正留下來的 Legacy，是玩家自己在一場場遠征中實際經歷過的事情。

## 戰鬥呈現

### 9×9 戰場

戰鬥維持 2D、格子化與符號化。

9×9 戰場優先使用 HTML DOM + CSS Grid 實作，不需要預設依賴 Canvas 或 WebGL。

每一格可以是獨立 DOM 元素，因此可自然支援：

- 點擊／觸控選取。
- 移動範圍高亮。
- 攻擊範圍與 AoE 預覽。
- 地形與阻擋資訊。
- HP、狀態與簡單標記。
- Damage number。
- CSS 命中／閃爍／震動效果。
- Tooltip 或手機點擊後詳細資訊。

### 操作原則

手機與桌機都應以簡單的 Tap / Click 為主要操作方式。

避免把精準拖曳、複雜手勢或滑鼠 Hover 設計成必要操作。

桌機可透過較寬的 Layout 把戰場與資訊面板左右排列；手機則可使用戰場在上、角色資訊與技能在下的直向配置。

## 故事與對話呈現

故事主要使用類似 Galgame / Visual Novel 的對話框呈現。

必要元素可以只有：

- 角色名稱。
- 對話文字。
- 簡單角色標誌、Icon 或有限立繪。
- 少量靜態背景。
- 選項按鈕。
- 簡單 Fade、Flash、Shake、Darken 等 CSS 視覺效果。

不要求大量 CG、角色 Live2D、逐格動畫或完整過場動畫。

敘事的主要力量來自：

- 對話。
- 玩家選擇。
- 戰鬥條件。
- 地圖事件。
- 事件前後的狀態改變。
- 玩家自己在 Run 中留下的記憶。

## 事件設計的 Presentation 欄位

未來每一個敘事／事件設計都應包含 `Presentation` 或「呈現方式」欄位，用來限制實作成本並確認事件不依賴不存在的美術資產。

可使用的呈現標籤例如：

- `Dialogue`
- `Choice`
- `Battle`
- `Background Change`
- `Simple FX`
- `Map Event`
- `System Message`

原則上，一個事件應優先用現有 UI、文字與戰鬥規則完成，而不是先新增大型專用美術需求。

## 美術資產原則

美術不是完全禁止，而是採「少量、高辨識度、可重用」方向。

優先順序：

1. UI 與 Typography。
2. CSS 視覺層級與狀態表現。
3. 符號／Icon。
4. 可重複使用的少量背景。
5. 必要時才增加角色立繪或特殊插圖。
6. 不把大量動畫、3D 或大量一次性 CG 納入 MVP 必要範圍。

## 與遊戲精神的關係

低具象化不是單純為了節省開發成本，而是作品的一部分。

《LEGACY COLLECTOR》希望玩家記住的不是「某段動畫有多華麗」，而是：

- 某一場戰鬥如何只剩 1 HP 活下來。
- 某個選擇帶來了什麼代價。
- 某個角色在關鍵事件中說了什麼。
- 某一次 Run 如何與之前完全不同。
- 自己如何一步一步理解四名角色。

因此技術、美術與敘事應共同服務同一件事：

**用最少的具象素材，留下足夠的空間，讓玩家自己的經歷成為畫面的一部分。**

## 目前確定的開發方向

- 主要平台：Web Browser。
- 主要技術：HTML / CSS / JavaScript / JSON。
- 主要戰鬥形式：2D 9×9 Tactical Grid。
- 主要戰場呈現：DOM + CSS Grid 優先。
- 主要敘事呈現：Galgame / Visual Novel 式對話框。
- 美術方向：Symbolic、低資產、少量可重用素材。
- 操作方向：Click / Tap first，支援手機、平板、桌機。
- 開發策略：MVP-first，不依賴傳統大型遊戲引擎。
- 世界呈現原則：保留玩家想像空間。

## 尚可於未來調整的部分

以下仍可依 Prototype 實測調整，不視為永久技術綁定：

- 是否在某些特殊戰鬥使用 Canvas。
- 是否導入輕量前端框架。
- 是否使用 PWA 安裝模式。
- 是否增加有限角色立繪。
- 是否為 Boss 或 Memory Awakening 製作少量特殊插圖／特效。
- 手機與桌機 HUD 的最終排列。

任何未來調整都應先回答一個問題：

**它是否真的改善遊戲體驗，還是只是增加製作成本？**
